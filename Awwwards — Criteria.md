## Awwwards — Criteria untuk Software (Desktop & Mobile Presentation)

### Referensi Kompetisi

Awwwards

---

# 1. Struktur Penilaian Resmi

Awwwards menggunakan sistem scoring berbobot:

* **Design — 40%**
* **Usability — 30%**
* **Creativity — 20%**
* **Content — 10%**

Berbeda dengan Red Dot, Awwwards menilai **experience layer**, bukan core product semata.

---

# 2. Design (40%)

### Definisi

Kualitas visual dan eksekusi estetika secara keseluruhan.

### Kriteria Teknis

* Visual hierarchy kuat
* Layout unik namun tetap readable
* Typography refined
* Color system intentional
* Motion design terintegrasi (bukan tempelan)

### Detail Penting

* First impression dalam 3–5 detik sangat krusial
* Micro-interactions meningkatkan perceived quality
* Pixel-level precision (spacing, alignment)

### Indikator Lolos

* Visual langsung menciptakan identitas kuat
* Tidak terasa seperti template

### Indikator Gagal

* Generic UI
* Visual bagus tapi tidak cohesive
* Overuse efek tanpa tujuan

---

# 3. Usability (30%)

### Definisi

Seberapa mudah user memahami dan menavigasi experience.

### Kriteria Teknis

* Navigation jelas dan konsisten
* Interaction tetap predictable meskipun visual kompleks
* Loading & transition tidak mengganggu flow
* Responsive behavior (desktop ↔ mobile)

### Detail Penting

* Creativity tidak boleh mengorbankan usability
* Scroll-based experience harus tetap terkontrol

### Indikator Lolos

* User tetap nyaman meskipun design eksploratif
* Tidak ada kebingungan navigasi

### Indikator Gagal

* Navigation tersembunyi tanpa affordance
* Over-animation yang memperlambat user

---

# 4. Creativity (20%)

### Definisi

Seberapa berbeda dan inovatif dibanding standar industri.

### Kriteria Teknis

* Interaction pattern unik
* Storytelling non-linear atau immersive
* Visual direction tidak generik
* Eksperimen pada layout atau flow

### Bentuk Implementasi

* Scroll-driven animation
* 3D / WebGL interaction
* Dynamic layout
* Narrative transitions

### Indikator Lolos

* Ada “signature experience”
* Mudah diingat setelah digunakan

### Indikator Gagal

* Mengikuti tren tanpa diferensiasi
* Kreativitas tidak relevan dengan produk

---

# 5. Content (10%)

### Definisi

Kualitas isi yang mendukung experience.

### Kriteria Teknis

* Copywriting jelas dan terarah
* Microcopy membantu navigasi
* Tone konsisten dengan brand
* Informasi tidak berlebihan

### Indikator Lolos

* User paham value produk tanpa berpikir
* Tidak ada ambiguity dalam pesan

### Indikator Gagal

* Placeholder content
* Copy terlalu generik atau tidak membantu UX

---

# 6. Developer Criteria (Tambahan Penting)

Selain juri design, ada penilaian teknis:

### Aspek Teknis

* Performance (load time, rendering)
* Accessibility (WCAG compliance)
* Responsive design
* Code quality

### Indikator Lolos

* Smooth di berbagai device
* Tidak ada lag pada animation-heavy interface

### Indikator Gagal

* FPS drop
* Layout break di mobile
* Heavy assets tanpa optimasi

---

# 7. Framework Evaluasi Internal

Gunakan ini sebelum submit:

### Visual

* Apakah ada visual identity yang kuat dalam 5 detik pertama?
* Apakah semua elemen konsisten secara sistem?

### UX

* Apakah user bisa navigate tanpa berpikir?
* Apakah animation membantu, bukan mengganggu?

### Creativity

* Apa yang membuat experience ini berbeda?
* Apakah ada elemen yang memorable?

### Content

* Apakah value produk tersampaikan jelas?
* Apakah microcopy membantu flow?

### Technical

* Apakah performa stabil di device low-end?
* Apakah responsive benar-benar konsisten?

---

# 8. Pola Submission yang Menang

Untuk software, biasanya bukan app-nya yang dinilai langsung, tetapi:

* Landing experience
* Product showcase site
* Interactive demo

### Struktur Umum

1. Hero section (impact tinggi)
2. Story tentang problem
3. Demonstrasi solusi (interactive)
4. Deep dive features
5. Closing narrative

---

# 9. Prinsip Kunci untuk Menang

* Design harus langsung “berbicara” tanpa penjelasan panjang
* Creativity harus terasa natural, bukan dipaksakan
* Motion harus memperjelas, bukan sekadar efek
* Experience harus terasa seamless dari awal sampai akhir

---

# 10. Perbedaan Kritis dengan Red Dot

* Red Dot fokus pada **produk**
* Awwwards fokus pada **presentasi & experience**

Untuk menang di Awwwards:

* Produk bagus saja tidak cukup
* Harus dikemas menjadi pengalaman yang engaging

---

# 11. Strategi untuk Software Kamu

Jika kamu sedang mengembangkan app:

### Layer yang perlu dibuat

* Core app → untuk Red Dot
* Presentation layer (website/demo) → untuk Awwwards

### Fokus Awwwards

* Visual storytelling
* Interaction design
* Emotional engagement

---

# 12. Ringkasan Strategis

Awwwards memilih:

* karya yang memorable secara visual
* experience yang terasa hidup
* execution yang presisi

Bukan sekadar:

* UI rapi
* atau UX standar
